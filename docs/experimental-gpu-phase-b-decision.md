## Genuine unresolved local-use evidence

1. **Native CUDA/vendor binary correspondence.** The acquired torch wheel contains CUDA, cuDNN, CUPTI, NVRTC, Intel OpenMP and other DLLs. Captured LICENSE/NOTICE provide substantial third-party evidence, but do not yet establish the applicable grants/version correspondence for every relevant proprietary runtime component. The eager test does not deliberately call cuDNN or CuTeDSL, but torch import/initialization may load bundled DLLs; avoiding a particular API is not evidence that its terms are irrelevant. Applicable CUDA/cuDNN/vendor use terms and their required assent cannot currently be specified reliably. This is the principal local-execution gate.
2. **Proprietary reference is not a redistribution-only clause.** Torch LICENSE lines 2138–2146 contain `LicenseRef-NvidiaProprietary` and state that use/reproduction/disclosure/distribution require an express NVIDIA license agreement. The concatenated source notice does not prove which wheel bytes incorporate that material, whether the tiny test uses it, or which separate agreement supplies the grant. Do not infer a prohibition on all torch use, but do not treat this as merely a missing redistribution notice either.
3. **CuTeDSL reference remains conditional.** LICENSE lines 1813–1818 refer specifically to `python/CuTeDSL` and an external EULA, rather than supplying full terms. The wheel inventory contains torch's `cutedsl`/CUTLASS integration modules; that alone does not prove inclusion or use of NVIDIA's separately licensed DSL package. The eager test does not invoke torch.compile. This reference is an uncertain correspondence issue, not a demonstrated mandatory click-through for the smoke test. Do not request acceptance of an uncaptured agreement.
4. **Python bundled binaries.** Captured Python documents include incorporated-software terms, but exact Microsoft runtime and Tcl/Tk grant/notice correspondence is not fully established. Tcl/Tk is not intentionally used; Microsoft runtime DLLs may be needed by the interpreter. Separate potentially needed runtime grants from unused optional components rather than assuming all bootstrap packaging gaps block execution. Current evidence does not complete that distinction.

No acknowledgement can substitute for the missing applicable grant/correspondence. No license acceptance is recorded by this decision.
