# Downloader design and Milestone 2D implementation

Date: **9 October 2026**. Status: **2D infrastructure implemented and tested offline**. Existing registry/evaluator/planner behavior is preserved. No real model weights, ComfyUI, inference, Resolve or frontend work occurred. The sections below “Historical 2C specification” preserve the original proposals; the implementation contract immediately below takes precedence where they differ.

## Implemented contract (2D)

The new `backend/director/installations` package provides five services:

| Service | Implemented responsibilities |
| --- | --- |
| ModelStorageManager | Configured root, ownership marker, exclusive OS root lock, validated contained paths, disk budget, immutable bundle activation and inventory-only removal |
| ArtifactVerifier | Regular-file/link/hardlink checks, exact size, streaming SHA-256, cancellation between chunks, changed-during-verification detection, explicit reports |
| HuggingFaceDownloader | Exact file allowlist and immutable pin; official pinned SDK in supervised process; private cache, supported login selection, bounded transfer, sanitized failures and process cancellation |
| InstallationJobManager | One asynchronous operation globally, durable JSON records, state transitions, progress, disk rechecks, staging verification, activation, verification/removal, restart reconciliation |
| LicenseAcknowledgementStore | Reviewed exact document/version/hash set, restrictions and component pins bound into digest, explicit acceptance record, timestamp/policy, no personal identity |

### Owned storage and activation

```text
DIRECTOR_MODEL_ROOT/
  .director/
    owner.json                     format + generated ownership id
    manager.lock                   lifetime OS lock
    hf-cache/<sha256>/             isolated SDK cache (fixture cache is tiny text)
    staging/<job-id>/bundle/       never exposed as installed
    installed/<model-id>/<job-id>/ checkpoint destinations + license texts + receipt
    installations/<model-id>.json active job/bundle pointer
    jobs/<job-id>.json             frozen manifest + state/progress/error
    journals/<job-id>.json         activation/removal intent
    acknowledgements/<id>.json    model/document digest, policy, acceptance time
```

Normal startup and read-only planning do not create an absent root. Explicit acknowledgement or installation creates the marked namespace. Existing unmarked `.director` directories are refused. Drive roots, UNC roots, external ComfyUI ancestors, traversal, redirected directories and hardlinked managed files are rejected. Snapshot file symlinks generated by the SDK are accepted only when they resolve inside the private cache; staged/installed files must be ordinary single-link files. Existing cache directories are checked before SDK writes.

Copies are flushed/fsynced, staged artifacts are hashed again, license text and a frozen receipt are written, and an intent journal precedes same-volume bundle rename. Only the atomic active-pointer replacement exposes that bundle. Receipt manifest digests/inventory reports are validated on lookup. No runtime mapping is performed. The old planner still shows logical flat paths and always reports `ready_for_installation=false`; managed paths add the owned bundle prefix.

Removal first inventories the bundle. Unknown files/directories, links or unsafe records block removal. It removes only the frozen component/license/receipt inventory; missing/corrupted component files may be removed safely. The active pointer is cleared before deletion, so partial deletion cannot leave a ready installation. Cache, incomplete/orphan bundles, job/journal/acknowledgement records and unrelated root files remain. No recursive blanket cleanup is used. Manual recovery is required for malformed receipts or unexpected additions. Repair and cache garbage collection are deferred rather than risking user data.

### Transfers, credentials and progress

`downloads` is an optional dependency extra pinned to `huggingface_hub==1.0.0`. Its installed public `hf_hub_download` signature was inspected: **no `tqdm_class` or public progress callback exists in that version**. The adapter observes `.incomplete` file sizes at 250 ms intervals where available. Those are approximate candidate bytes (Xet may allocate differently), capped by expected size. Cache completion also reports candidate size. Verified bytes come only from hashing; no reliable ETA or resumed-byte claim is provided.

Each transfer uses `repo_id`, exact `filename`, full `revision`, private `cache_dir`, fixed HTTPS Hub endpoint, bounded SDK metadata/read timeouts, and a configurable overall time budget (default one hour per artifact). No unfiltered snapshot, executable repository code, arbitrary remote URL or manifest-provided headers are accepted. Integrity is verified in the parent before copy and again in staging. A network/worker error fails the job with a category, never a raw remote exception.

Public access passes `token=False`. Explicit `DIRECTOR_HF_AUTH=login` passes `token=True` so the SDK resolves its supported login/token environment mechanisms in the worker. Tokens do not appear in process command arguments, manifests, jobs or API bodies. Debug output, telemetry and raw SDK logging/stdout/stderr are disabled in that worker. The SDK's file token store is not encrypted by Director; no Windows Credential Manager adapter is implemented.

Cancellation requests set a flag. The supervisor stops and joins the transfer process before reporting cancellation. Copies/hash loops check cancellation between chunks. Cancellation cannot interrupt the short commit section. Worker termination can leave SDK partial files/locks; a later explicit attempt can reuse intact pinned cache via the SDK, but HTTP/Xet resume is not guaranteed or live-tested. There is no automatic retry loop or startup network resume.

### Preconditions and readiness

Real downloads are disabled unless explicitly configured; no endpoint enables them. Wan also defaults to `artifact_installation_reviewed=false` with no complete reviewed license text documents, so it is blocked even if the switch is changed. All installable components require a pin, exact positive size and SHA-256. Legacy mocks stay valid and non-installable. The opt-in fixture has fictional identities and an offline-only provider; it can never be sent to Hugging Face by this manager.

License documents contain id/version/source/text/SHA-256; text hashes are validated by Pydantic. Acceptance must be JSON boolean true and match the document-set digest/policy. Changed documents/restrictions/component pins invalidate it. The request must also match the complete frozen manifest digest. No name/address/account id is recorded. Product acknowledgement does not substitute for publisher gating or provenance/NOTICE obligations.

Preflight conservatively requires three times the expected artifact bytes plus 16 MiB, budgeting private cache and staging rather than inventing an exact software budget. Checks repeat before transfers, on progress and during copies; unknown/insufficient free space blocks or fails. This is not a reservation. Unknown hardware/runtime requirements remain generation limitations, not fabricated artifact incompatibility. `ready` describes artifacts only and `generation_ready` remains false.

### Lifecycle and recovery

| From | Allowed next states |
| --- | --- |
| checking | downloading, verifying, installing (removal), failed, cancelled |
| downloading | verifying, failed, cancelled |
| verifying | installing, ready (verification-only), corrupted (verification-only), failed, cancelled |
| installing | ready (activation), not_installed (removal), failed |
| ready / failed / cancelled / corrupted / not_installed | Terminal job; a new job is required |

An absent installation starts as `not_installed`. One root lock plus one active job globally prevents conflicting installs/verify/remove. Duplicate installed requests return 409; absent removal returns 404. No idempotency-key contract is implemented. Cancellation of an already cancelled job is idempotent; completed/committing jobs return 409.

On restart, a nonterminal install whose pointer/receipt matches its job is rehashed and reconciled to ready/corrupted. An interrupted removal with no pointer becomes not_installed with cleanup_pending. Other interrupted jobs fail with interrupted and retain staging/cache. A rename without a committed pointer stays inactive. Malformed persisted records fail closed; no guessed repair or network request occurs. Journals record intent, not a promise of full transaction rollback. Previously completed job status is historical; installation status rehashes active artifacts and is the current readiness source.

### Implemented API

All routes proposed below exist except repair. Their exact current paths and PowerShell examples are in [README.md](../README.md). Start returns 202 with a full Job (`id`, `state`, top-level candidate/verified/expected bytes, frozen manifest, verification, error). Acknowledgement returns 201 with `id`. Neither a credential_reference nor an idempotency key is accepted. Error details contain code/message; there are no speculative retryable/recovery_action fields. Existing GET response meanings remain unchanged.

POST/DELETE require `DIRECTOR_MANAGER_TOKEN` (at least 32 characters), `X-Director-Key`, local Host and matching Origin if supplied. Bind Uvicorn to loopback. Missing key is 503, unauthorized is 403, unknown id is 404, conflicts are 409, unmet preconditions are 412, malformed bodies are 422. These are local controls, not a multi-user authentication system.

### Verified limits

Offline tests cover successful fixtures, hash/size/missing data, paths, Windows junctions, hardlinks, disk rechecks, failed transfers, cancellation/supervisor termination, duplicate operations/root locks, recovery, acknowledgement changes, corrupted receipts, safe removal and APIs. Real HTTP/Xet retries/resume, Hub credentials, signed redirects, cache eviction, shared artifacts, Windows power-loss durability and every crash boundary are untested. Standard-library path checks are not hardened handle-level race isolation against hostile same-user changes. Installed status synchronously hashes files and may block a concurrent manager operation while scanning large weights. Keep large transfers disabled until separately authorized validation.

## Proposed module boundaries

Keep the existing registry, pure evaluator, read-only planner, and HTTP wiring. Future implementation can add a small `backend/director/installations/` package; do not create empty adapters now. One backend process, one installation worker at a time, and durable JSON records are sufficient initially. No distributed queue or database is needed.

| Proposed component | Responsibility and boundary |
| --- | --- |
| `HuggingFaceDownloader` | Obtain metadata and selected pinned files using the official SDK; report transfer observations. It never activates a model or declares it ready. |
| `ModelStorageManager` | Own paths, volume checks, staging, commit journal, activation, leases, quarantine, and safe removal. It never accepts arbitrary client paths. |
| `InstallationJobManager` | Freeze the manifest, enforce transitions/locks, supervise a worker, persist progress/errors, coordinate cancellation and restart reconciliation. |
| `ArtifactVerifier` | Check regular-file identity, exact length, and full streaming SHA-256 without loading model tensors or executing code. Produce verification records bound to the manifest. |
| `LicenseAcknowledgementStore` | Record explicit acceptance against exact license documents and component revisions; no tokens or legal assumptions. |

Suggested methods are design contracts, not existing callable APIs: downloader `inspect(component)` / `fetch(component, cache, progress)`; storage `preflight` / `stage` / `activate` / `remove`; jobs `start` / `get` / `request_cancel` / `reconcile`; verifier `verify_file` / `verify_bundle`; acknowledgements `record` / `check`.

### Separate installation from generation readiness

Future installation `ready` means **all selected model artifacts are present and verified in an activated bundle**. It does not mean ComfyUI is installed, hardware is certified, or generation works. Expose generation readiness separately, initially false/unknown; never change `support_status` because a download succeeded.

The current planner deliberately combines artifact and runtime/hardware gaps, and always returns `ready_for_installation=false`. Keep that behavior throughout 2C. For 2D, propose additive artifact-installation blockers versus generation prerequisites: pins, integrity, licenses/access, path safety, and storage must pass before downloading; unknown runtime/VRAM remains a generation warning/blocker. This avoids requiring a generation benchmark before obtaining the weights needed for that benchmark. Any future planner change needs explicit tests and documentation; do not reinterpret legacy compatibility fields.

## Storage and activation design

Proposed layout beneath the configured model root, created only by a future authorized installer:

```text
model_root/
  .director/
    jobs/<job_uuid>.json
    acknowledgements/<document_set_digest>.json
    locks/
    hf-cache/                   Director-owned SDK cache only
    staging/<job_uuid>/bundle/  isolated incomplete bundle
    trash/<operation_uuid>/    quarantined owned bundles
    installations/<model_id>.json   active pointer/commit journal
  bundles/<model_id>/<bundle_uuid>/
    diffusion_models/<filename>
    text_encoders/<filename>
    vae/<filename>
    receipt.json
    licenses/
```

Each immutable receipt stores the canonical manifest digest, repo/revision/filename, size/hash, verification timestamps, license-document digests/acknowledgement reference, and owned relative paths. UUIDs come from the server. Manifest destinations retain their existing logical ComfyUI folder meaning. Proposed bundle destinations are a future storage feature; today's planner still shows its original flat paths.

A future runtime adapter can map only the active bundle into ComfyUI using the documented [extra model paths configuration](https://raw.githubusercontent.com/Comfy-Org/ComfyUI/master/extra_model_paths.yaml.example). Never expose staging or cache to ComfyUI. Mapping/refresh behavior must be tested later; no runtime integration happens in 2C/2D.

1. Validate the manifest again; freeze its canonical digest and selected pins. Reject client-supplied repository URLs, destination overrides, or branch fallback. Acquire an OS-backed storage-owner lock and per-model operation lease; fail a second backend writer explicitly.
2. Accept only a configured local disk with supported large-file and rename behavior initially, targeting NTFS on Windows. Reject root/drive-root destinations, UNC/network roots, unsafe names, escaping links/reparse points, and unowned existing paths. Check resolved containment, case-insensitive duplicates, full path length, and parent types. Windows handle/reparse checks immediately around mutations must reduce the check/use race; simple `Path.resolve` alone is insufficient protection for an installer. Treat external same-user modification as outside a hard isolation guarantee and reverify before use.
3. Measure cache, staging, destination and journal volumes. Keep staging and the bundle destination on the same volume. Reserve a conservative application budget under the lock, but state that other applications can consume disk space. Recheck before every file/copy, periodically during transfer, and before activation.
4. Budget remaining SDK cache writes, staging copies, Windows cache duplication, retained old bundles, license/receipt metadata, and an explicit configurable safety margin. Do not hard-code a universal model overhead. With one cache copy plus one bundle copy, an empty system needs at least `2 × 9,828,025,775 = 19,656,051,550` weight bytes before margin; SDK duplication may increase this. Reuse reduces budget only after hashing; partial/cache size is not proof of valid content.
5. Obtain files in the owned cache, copy to staging as regular files, and verify the staged bytes after copying. No hardlinks to a mutable SDK cache and no in-place overwrite of an active bundle. Only a complete verified receipt can proceed.
6. Persist a commit-intent journal; flush/close files, rename the complete staging bundle to a new immutable bundle directory on the same volume, then atomically replace the active-pointer JSON. The pointer update is the activation boundary. Never copy a directory across volumes and call it atomic. File/directory moves and the journal are not one filesystem transaction; receipt validation and restart reconciliation close that gap. Windows sharing locks/antivirus can prevent a rename; retry within bounds or fail without announcing ready. Do not promise power-loss durability on every filesystem.
7. Mark the job successful only after the active receipt is read back and valid. Keep the previous bundle until activation and readers' leases have ended. A crash before pointer replacement leaves the old bundle active; a renamed orphan is not ready. A crash after pointer replacement is reconciled from the journal/receipt and file verification, not the last saved progress percentage.

## Transfer, resume, cancellation, and recovery

Use exact-file `hf_hub_download(repo_id, filename, revision=<full commit>, cache_dir=<owned cache>, token=...)`, rather than an unfiltered repository snapshot. The documented [download API](https://huggingface.co/docs/huggingface_hub/en/package_reference/file_download) exposes metadata inspection, caching and custom `tqdm_class` progress. Pin/test the SDK version in 2D; it is not installed or added as a dependency now.

The [SDK source](https://raw.githubusercontent.com/huggingface/huggingface_hub/main/src/huggingface_hub/file_download.py) shows partial HTTP resume and retry logic. Resume is a transport/version capability, not a guaranteed number of saved bytes: HTTP range refusal may restart a file, and Xet reconstructs files differently. Reinvoke the same pinned artifact using the intact owned SDK cache; do not invent a `resume_download` argument absent from the inspected API or manipulate internal partial files. On resume, compare pinned metadata again and hash the complete output. Benchmark HTTP/Xet behavior and cache locks with the pinned SDK on Windows before promising resume. A killed transfer may need to restart.

Report operation, phase, component, expected bytes, observed transfer/reconstruction bytes, verified bytes, resumed/cache observations, timestamps and an error code. Progress callbacks are transport observations, not proof of a complete file. Throttle notifications, keep transfer and verification progress separate, allow a reset when transport restarts, and show unknown totals/ETA as null. Cached file completion advances only after local verification. Never equate 100% transfer with installation readiness. Initial clients can poll; SSE is optional later, not required for the first implementation.

Run the SDK in an isolated child process so an unresponsive synchronous call cannot hold the API thread. Request cooperative cancellation between files and verification/copy chunks. The inspected high-level API does not provide a Director cancellation-token contract; a callback exception alone is not a portable cancellation guarantee, especially for Xet. After a bounded grace period, terminate only that worker, confirm exit, then release its locks. Keep SDK-managed partial cache data resumable where supported; do not remove files while a worker still writes them.

During the short journal/rename/pointer commit section, defer cancellation until its result is known. If activation succeeded, return completed/ready with cancellation too late; do not label the installed bundle cancelled. Before activation, cancellation never creates an active pointer. Pending cancellation is a flag, not a terminal result. Timeouts do not authorize marking a still-running worker cancelled.

Use bounded connect/read timeouts and a whole-job/stalled-progress budget. Retry transient network errors, 429 with Retry-After, and selected 5xx with capped exponential backoff/jitter; account for SDK internal retries so the total is finite. Refresh transient signed locations through the SDK, never persist signed CDN URLs. Authentication failures, absent revision/file, unsafe path, disk exhaustion, and integrity mismatch require a specific failure decision, not endless retry or fallback to main. A hash failure quarantines the candidate/cache result; one explicitly requested clean retry can repair it. Offline verified cache reuse may succeed only against the frozen inventory and exact hashes.

## Authentication and acknowledgement

For these public repositories, pass `token=False` to avoid implicitly sending an unrelated login token. Fix the Hub endpoint to HTTPS `https://huggingface.co`; do not accept arbitrary endpoints, proxies, auth headers, or download URLs from a client manifest. The SDK handles legitimate Hub/CDN/Xet redirects; test credential stripping and redact signed URLs. Never disable TLS validation.

For future gated models, use an explicitly selected read-only/fine-grained credential from Windows Credential Manager (future adapter), or a clearly documented Hugging Face login token store. See [SDK authentication](https://huggingface.co/docs/huggingface_hub/en/package_reference/authentication) and [environment/token behavior](https://huggingface.co/docs/huggingface_hub/en/package_reference/environment_variables). Read tokens server-side and supply them in memory to the worker over private IPC, never command-line arguments, manifest/job JSON, Git, API responses, or logs. Disable debug request dumps; do not log raw SDK exceptions that may contain headers or signed URLs. A credential reference is not the token. Explain that Hugging Face's default file token store is not encrypted by Director. No token is requested or inspected in this milestone.

Before installation, assemble the exact pinned license/card/NOTICE document set, preserve its bytes and hashes, and display its restrictions and obligations. Record explicit acceptance with document-set digest, component revisions, policy version and UTC timestamp for the local user. Missing documents/provenance block the acknowledgement package, not an automatic guessed acceptance. Changed terms/revisions invalidate an earlier acceptance. Apache-2.0 acknowledgement is Director's product policy, not a claim that Hugging Face or Apache requires a click-through gate. Acknowledging a summary does not replace required attribution files or upstream gated-repository approval.

Future mutation APIs also need localhost-only binding, trusted Host/Origin checks and a local authorization/session mechanism; localhost by itself does not prevent a malicious webpage from issuing requests. Never accept credentials on an installation request. These are downloader API design requirements, not new restrictions on today's read-only API.

## Installation lifecycle

Persist **job phase** separately from **active installation state**. A failed repair job must not turn a healthy prior installation into failed. State transitions are server-controlled and journaled; clients cannot assign ready.

| Job phase | Valid next phases / meaning |
| --- | --- |
| `checking` | downloading; verifying for cache reuse/local verification; installing for uninstall; failed/cancelled if preflight cannot complete |
| `downloading` | verifying once every required candidate is complete; failed/cancelled otherwise |
| `verifying` | installing after complete staged verification; ready after successful verification-only; corrupted on mismatch; failed on unreadable/interrupted checks; cancelled before commit |
| `installing` | ready only after committed installation; not_installed after committed uninstall; failed before a confirmed commit. Cancellation is deferred during commit. |
| `ready`, `not_installed`, `failed`, `cancelled`, `corrupted` | Terminal job outcome; a retry/repair creates a new job, preserving history. No direct failed/cancelled -> ready transition. |

Verification-only of an absent installation ends failed/not_installed as appropriate to its operation, never ready. A post-rename pre-activation error remains failed with an orphan candidate. Restart moves interrupted nonterminal work into checking/reconciliation, then either recovers a committed outcome or ends failed with `interrupted` and an explicit resume/repair action. Do not silently restart large network transfers on application startup.

| Active installation state | Transition and recovery |
| --- | --- |
| `not_installed` | checking on install request; ready only after verified commit |
| `checking`, `downloading`, `verifying`, `installing` | Display initial-install work while no valid active bundle exists; failure/cancellation leaves no ready model |
| `ready` | verifying during explicit verification (generation leases paused); ready again only on pass; corrupted on proven mismatch; unknown/checking or failed on access error, never a false hash-mismatch claim |
| `corrupted` | checking on repair; verifying -> installing -> ready after a clean verified replacement; generation remains disabled |
| `failed`, `cancelled` | checking on an explicit new attempt; retained partials are not installed |
| any installed state | checking -> installing -> not_installed for successful uninstall; blocked while runtime/read leases exist |

A healthy old bundle stays ready during replacement/repair unless checking discovers its corruption; report the replacement job independently. A filesystem change or inconsistent/missing receipt invalidates readiness pending verification. Future runtime use requires a current valid receipt and separate runtime/generation checks.

## Verify, repair, and uninstall

Verification streams every installed file through SHA-256 and exact-size checks against the recorded pinned inventory, independent of Hub connectivity. It never trusts matching filenames or SDK cache existence. Missing/changed bytes mark the active bundle corrupted; an unavailable drive is an access failure, not evidence of corruption. Capture file identity/stat around reads and reject changes during hashing.

Repair first verifies, then reuses only files that pass. Copy valid files into a fresh staging bundle, fetch only missing/bad components where access allows, verify the complete staged inventory, and activate as above. Preserve the old healthy bundle through failure; never repair it in place. A corrupted old bundle cannot be used for inference.

Uninstall obtains the model lease, stops or refuses active runtime users, journals deactivation, removes the active pointer, and moves only receipt-owned bundle directories into owned trash before deleting. Reconcile interrupted removal from tombstone/journal; report cleanup_pending if locked files remain. Never recursively delete paths read from an untrusted request/receipt without root containment, ownership, link checks and resolved target validation. Do not follow reparse points during traversal. Missing/damaged receipts require manual recovery rather than guessing ownership. Retain acknowledgement history and job records. Default to retaining the private SDK cache; garbage collection is explicit, uses supported cache management, and respects other model references. Never touch a user's general Hugging Face cache or arbitrary ComfyUI installation.

## Proposed API — not implemented

Keep the existing GET routes unchanged. Future request schemas reject unknown fields and arbitrary paths/repos/tokens. Model/job IDs are server-resolved. Manifest digest plus an idempotency key prevents a stale plan or repeated click starting a different installation. One active operation per model; initially one transfer globally.

| Method and path | Proposed behavior |
| --- | --- |
| `POST /api/models/{model_id}/installations` | Start authorized install; body: manifest_digest, acknowledgement_id, optional credential_reference. 202 with job_id/state/progress_url; completed matching install is an idempotent no-op. |
| `GET /api/installation-jobs/{job_id}` | 200 durable phase/progress/error/cancel_requested; no credentials or signed locations |
| `POST /api/installation-jobs/{job_id}/cancel` | 202 cancellation requested; idempotent for an already cancelled job; 409 if completion/commit makes cancellation too late |
| `GET /api/models/{model_id}/installation` | 200 active artifact state/receipt summary, separate generation readiness and current job |
| `POST /api/models/{model_id}/installation/verify` | 202 local verification job |
| `POST /api/models/{model_id}/installation/repair` | 202 repair job with frozen inventory/acknowledgement; never upgrades to a moving branch |
| `DELETE /api/models/{model_id}/installation` | 202 removal job; default keep-cache; unknown model 404, already absent is an idempotent no-op |
| `GET /api/models/{model_id}/license-requirements` | 200 pinned document set, hashes, restrictions, required acceptance; no guessed source documents |
| `POST /api/models/{model_id}/license-acknowledgements` | Record explicit accepted=true plus document_set_digest and policy_version; return acknowledgement_id; does not install anything |

Proposed errors retain FastAPI's `detail` envelope with a structured code/message/blockers value: 404 unknown ID; 409 busy/stale digest/in-use/too-late cancellation; 422 malformed request; 412 unmet preconditions (license, access or storage); 503 worker/service unavailable. ## Milestone 2D recommendation and acceptance checks

Implement these services incrementally with tiny local fixture files and a fake transport first: path ownership, verifier, state/receipt/acknowledgement persistence, controlled cache/staging worker, journaled activation and recovery, then endpoints. Pin and test the chosen Hugging Face SDK; close license/provenance document gaps before enabling real Wan requests. Actual model transfers require the next user-authorized scope; runtime installation and inference remain separate.

Test tampered/truncated/wrong-size data, pointer-text mistaken for weights, path/reparse races, case conflicts, partial and resumed files, HTTP/Xet restarts, offline cache verification, token redaction/redirect handling, 401/403/404/429/5xx/timeouts, disk-full races, Windows sharing failures, every valid/invalid transition, cancellation before/during commit, crash at every journal boundary, acknowledgement invalidation, stale/idempotent requests, damaged receipts, safe repair/uninstall, and shared-cache references. Downloader fixtures must not require real weights, GPUs, ComfyUI, or Resolve. Passing these tests proves installation behavior for their cases, not model generation compatibility.
## Milestone 3B UI integration

Frontend review now uses existing manager APIs; transport and lifecycle remain unchanged. The plan adds artifact-only preflight separate from the conservative combined generation plan. Manager/preflight share metadata gates; startup still requires explicit acknowledgement of the reviewed document digest, matching manifest digest, safe owned paths, disk space and no concurrent operation.

The UI installs only the offline fixture with explicit backend/development flags. Production hides fixtures; Wan and every real-model installation control remain disabled. Missing keys/documents, stale reviews, blockers and uncertain responses fail closed. Acknowledgement and confirmation are separate actions. No runtime or repair/removal UI was introduced.
